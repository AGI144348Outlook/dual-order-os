# Components

Reusable parts for Dual Order OS: algorithms, data-access tools, registries, storage interfaces, symbolic operators, and evaluation mechanisms.

This area catalogs components that can be examined and recombined across frameworks. It does not automatically make a documented operation executable, validate a claim, or activate a dependency.

## Navigation

- [Component index](INDEX.md): existing local parts and external candidates.
- [Matrices](../matrices/): content organized by kind.
- [Indices](../indices/): alternative lookup directions over the same parts.
- [Libraries](../libraries/): executable code already present in this repository.

A component record can serve as an index card. The card describes and points to a component; the indexer and executable implementation perform operations.

For each future component, record identity, source repository/path/commit, purpose, input/output contract, implementation reference, dependencies, permissions, test evidence, and review status. Keep semantic profiles replaceable and preserve their provenance. These are proposed record fields, not new glyph invariants or a completed runtime schema.

## Location and status

Dual Order OS was established for decomposing frameworks into reusable parts. Development has also occurred in Echo Green Future and Group Canvas; their contents are not automatically present here.

The requested full Genesis Documentary transfer has not been published. Its integration inbox remains in Echo Green Future. The external links in this catalog are references, not claims that a complete copy exists in Dual Order OS.

This change adds organization and references only. It does not integrate Echo, deploy the cabinet, implement a game engine, or introduce training dependencies.
